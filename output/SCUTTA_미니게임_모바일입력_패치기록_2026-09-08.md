# SCUTTA 미니게임 렌더링·모바일 입력 보완

기존 모바일 안정성 패치에 추가한 로컬 변경이다. 운영 배포는 수행하지 않았다.

## 적용 범위

- 탁구공 게임에서 완전히 화면 밖에 있는 라켓의 그리기를 생략한다. 테두리가 일찍 사라지지 않도록 좌우 2px 여유를 둔다. 이동·충돌·점수 계산은 그대로 수행한다.
- 한 라켓의 손잡이와 머리를 그릴 때 같은 기하 정보를 재사용한다.
- 플레이 중 입력 직전/직후 상태를 연속 두 번 그리던 부분을 최종 상태 한 번으로 줄인다. 입력 처리 중 충돌한 경우에는 종료 상태를 정상적으로 그린다.
- 마우스·터치·펜의 주 입력은 `pointerdown`에서 즉시 처리한다. 뒤따르는 물리 `click`은 다시 점프시키지 않는다. 포인터 없이 발생하는 접근성 click은 유지한다.
- 두 번째 손가락, 마우스 우클릭과 펜 보조 버튼을 점프 입력에서 제외한다. 게임 키를 누른 채 유지해도 반복 점프나 기본 스크롤을 발생시키지 않는다.
- 탁구공 canvas에만 `touch-action: none`을 적용해 게임 중 손가락 이동·핀치가 브라우저 제스처로 전환되지 않게 한다.
- 두 미니게임 전체화면에서 텍스트 선택, iOS 터치 설명 메뉴, contextmenu 및 dragstart를 억제한다. 일반 페이지의 텍스트 선택·복사·확대는 변경하지 않는다.
- 동전 게임에서 Enter를 계속 누른 채 한 판이 끝나면 다음 판이 실행되는 문제를 막는다. 최초 Enter, Space, 클릭과 터치의 기존 동작은 유지한다.

공·라켓 그림, 해상도, 그림자와 blur, 게임 속도·난이도·충돌 규칙, 설치 아이콘과 서비스 워커 갱신 정책은 변경하지 않았다. 렌더링 캐시, 해상도 자동 하향, Worker 이전은 추가하지 않았다.

## 그림과 작업량 비교

변경 직전 실제 renderer와 변경 후 renderer를 같은 Chromium Canvas에서 비교했다. DPR 1·1.5·2, seed 2개, 초기 상태 및 좌우 경계를 포함한 19개 상태씩 총 114개 조건이다. 일부 상태는 소수점 좌표, 상승·하강 속도, 종료 상태를 포함한다. 비교한 모든 RGBA 값이 같았다.

| 한 프레임의 호출 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 첫 화면의 gradient 생성 | 20 | 2 |
| 라켓 한 쌍이 보일 때 gradient 생성 | 20 | 8 |
| 보이는 장애물 한 쌍의 geometry 계산 | 4 | 2 |
| 정상 플레이 탭 한 번의 즉시 draw | 2 | 1 |

이는 불필요한 작업 감소를 확인한 수치다. iPhone·iPad의 실제 FPS 상승률을 측정한 결과는 아니다. 픽셀 비교 결과는 `paddle-mobile-pixel-check-2026-09-08.json`에 저장했다.

## 완료한 검증

- 프런트엔드 기존 테스트 101개, lint, TypeScript 및 production build, PWA 산출물 검사 통과.
- 탁구공 브라우저 16개 시나리오·19개 검증 통과: 누름 직후 반응, 놓을 때 추가 점프 없음, 취소 후 다음 탭, 접근성용 click, 빠른 두 탭, 비주포인터·펜 보조 버튼, 반복키, 우클릭, 게임 중 핀치·스크롤 방지, 종료 및 외부 텍스트 선택 유지.
- 동전 게임은 Chromium 데스크톱·모바일 에뮬레이션에서 Enter 유지 시 요청 2회 발생을 재현하고 수정 후 1회임을 확인했다. 일반 Enter·Space·클릭·터치·길게 누르기와 외부 폼 선택은 유지된다.
- 생성된 설치 아이콘 6개와 manifest, 총 7개 파일의 SHA-256이 변경 전후 동일하다.
- 기존 로컬 서버 `http://127.0.0.1:8000`의 health와 홈이 200 응답하며, 제공하는 게임 JS가 최신 빌드와 동일함을 확인했다. 운영 배포는 하지 않았다.
- git diff --check 통과. 이번 미니게임 추가 변경에는 백엔드 수정이 없어 기존 백엔드 110개 테스트를 재실행하지 않았다.

## 입력과 플랫폼 한계

Windows Chromium에서 실제 브라우저 포인터·키보드 이벤트와 CDP 터치 이벤트를 사용해 누름 직후 게임 시작, 마우스 600ms/터치 850ms 유지, 놓을 때 추가 입력 없음 등을 확인했다. 애니메이션과 입력에 의한 draw를 구분하기 위해 검사에서는 rAF와 게임 시간을 제어했다. 합성 이벤트 검사는 OS의 실제 메뉴·접근성 서비스 실행과 구분한다.

노트북 터치패드의 '탭하여 클릭'은 OS/드라이버가 손을 뗀 뒤 클릭으로 인식할 수 있다. 이 경우 웹 코드에는 최초 손가락 접촉 신호가 전달되지 않으므로 `pointerdown`으로도 실제 접촉 시점까지 앞당길 수 없다. 터치패드의 물리 버튼 누르기 또는 Space 키로 누름 즉시 입력을 사용할 수 있다. 터치스크린의 직접 접촉과는 다른 입력 경로다. [Microsoft 터치패드 설명](https://learn.microsoft.com/en-us/windows/apps/develop/input/touchpad-interactions), [제스처의 인식 조건](https://learn.microsoft.com/en-us/windows/win32/uxguide/inter-touch)

iOS Safari·Chrome, Android, VoiceOver·TalkBack 실기기는 사용하지 않았다. 따라서 OS 고유 메뉴·제스처·보조기술까지 검증 완료로 간주하면 안 된다. iPhone 13과 iPad에서는 저전력 모드를 끄고 발열이 없는 상태의 비교가 남아 있다. WebKit의 저전력·열 제한에 따른 프레임 제한은 이번 렌더링 수정으로 해제할 수 없다. [WebKit 프레임 제한 구현](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/platform/graphics/AnimationFrameRate.cpp)
