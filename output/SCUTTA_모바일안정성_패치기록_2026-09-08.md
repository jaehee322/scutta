# SCUTTA 모바일 안정성 패치

기준: main 168e79d의 로컬 수정. 운영 배포·계정 변경·운영 DB 변경은 수행하지 않았다.

## 기존 사용자 호환성

- 설치 앱 이름, 아이콘, manifest id/scope/start_url, 서비스 워커 갱신 방식 및 캐시 정책 유지.
- 빌드 전후 apple-touch icon, favicon, maskable icon, PWA 아이콘 3종, manifest 총 7개 파일의 SHA-256 동일.
- 기존 관리자 비밀번호, auth_version, 활성 세션 유지. 최초 관리자가 없는 DB에만 BOOTSTRAP_ADMIN_PASSWORD 필요.
- 동전·탁구공 게임 규칙, 경기·정산 API 계약과 DB 스키마 변경 없음.

## 변경 내용

1. API 시간 제한·취소를 응답 본문 수신까지 유지한다. 인증 전환 시 이전 일반 요청을 취소하고, 이전 401이 새 로그인 상태를 지우지 않게 한다.
2. 첫 인증 조회만 60초 기다리며 5초 뒤 연결 안내와 수동 재시도를 제공한다. 자동 요청 재시도는 추가하지 않았다.
3. 정산 설정은 저장 중 입력을 잠근다. 완료된 탁구공 게임 점수 큐는 화면 이동 뒤에도 앱 인스턴스 안에서 유지하고 저장 중·실패를 표시한다. 계정 전환 시 이전 큐는 폐기한다.
4. 동전 게임에 종료 버튼과 Escape 처리를 추가한다. 요청 처리 중에는 잠그며 재진입하면 기존 활성 게임을 이어간다.
5. 선택 메뉴 위치를 가시 viewport 기준으로 계산한다. 키보드가 없는 기존 화면의 배치는 유지한다.
6. 기존 설치 버튼의 안내를 기기별 번호 단계로 확장한다. 공유 버튼 모양, 메뉴 스크롤, 메뉴가 없을 때의 대안, 카카오톡 주소 복사, 기존 계정 사용을 설명한다. 데스크톱 fallback도 유지한다.
7. 업데이트 안내를 닫은 뒤 홈의 계정 설정에서 다시 열 수 있게 한다. 활성화·재로드 정책은 변경하지 않았다.
8. 동전 CSS 마스크 PNG를 418678바이트에서 122549바이트로 약 70.7% 축소한다. CSS에서 쓰지 않는 RGB를 단색화하여 압축했으며 모든 알파 값과 1254×1254 크기를 유지했다.
9. 최초 관리자 기본 비밀번호를 제거하고 새 DB 배포·CI 초기화 설정을 보완했다. 기존 백업의 확인·분리 DB 복원·초기화 전 절차를 backend/OPERATIONS.md에 정리했다.

- git diff --check 통과.

## 검증의 한계와 이번 범위

실제 iPhone·Android OS 키보드·설치 UI·앱 강제 종료는 미검증이다. 기기 식별자를 바꾼 Chromium 검사는 Safari·카카오톡 자체 실행이 아니다. 운영 백업 복원과 Docker 이미지 재빌드는 수행하지 않았다. Docker 데몬은 실행되지 않은 상태였다.

PWA 강제 갱신 방식 변경, DB 잠금/SQLite 동시성 수정, 안티치트, 세션 만료 정책 변경, 의존성 잠금, 영구 오프라인 큐는 이번 범위에서 제외했다. Windows 패키지 목록만으로 Linux 배포 의존성을 고정하지 않았다. 운영 백업 확인 및 복원은 운영 담당자가 별도 DB에서 절차에 따라 수행해야 한다.

게임 점수 대기 큐는 앱 프로세스가 살아 있는 동안의 화면 이동만 보호한다. OS 강제 종료·오프라인 영구 저장을 보장하지 않는다. 원격 관리자 초기화와 이미 진행 중인 점수 제출의 완전한 분리에는 서버 측 세대 정보가 별도로 필요하다.
