# SCUTTA 운영 안내

코드를 수정하지 않고 일상 운영할 때 참고하는 문서입니다. 점검 기준일은 2026-09-13입니다. 실제 Render 운영 DB에는 접속하지 않았고, 이번 코드 변경은 운영에 배포해야 반영됩니다.

## 이번 최종 수정본 반영

1. 변경 파일과 새 파일을 함께 커밋하여 Render에 연결된 GitHub 배포 브랜치에 올립니다. 과거 `output` 파일과 데모 스크립트 삭제도 의도된 정리입니다. `.env`, DB 파일, `.backups`는 올리지 않습니다.
2. GitHub Actions의 backend·frontend·container 검사를 확인합니다. Render 자동 배포가 꺼져 있다면 해당 서비스에서 최신 커밋을 수동 배포합니다.
3. 배포가 Live가 되고 시작 로그의 DB 마이그레이션이 성공했는지 확인합니다. 현재 최신 revision은 `20260913_0014`이며 시작 명령이 자동 적용합니다. 기존 관리자와 기록을 초기화할 필요가 없습니다.
4. 관리자·선수 로그인, 일반 경기 조회, 개인 리그·단체전 결과 정정, 정산 화면을 확인합니다. 운영에 시험 결과를 남기면 실제 경기와 혼동되지 않게 하고 확인 후 해당 기록만 정정합니다.
5. 설치 앱에서 새 버전 안내가 나오면 입력을 마친 뒤 업데이트합니다. 이번 버전을 한 번 적용한 뒤부터 실행·복귀 시와 사용 중 1분 간격의 업데이트 확인이 작동합니다. 설치 아이콘과 계정은 그대로입니다.

대회와 일반 경기의 같은 날짜 기록이 생긴 이후에는 과거 DB 제약으로 되돌릴 수 없습니다. 과거 버전으로 무작정 롤백하거나 DB를 초기화하지 말고 실패 로그와 현재 revision을 확인합니다. 새 마이그레이션은 충돌 기록이 있는 되돌리기를 거절하여 데이터를 보호합니다.

## 관리자 화면에서 할 일

| 작업 | 화면 경로 |
| --- | --- |
| 선수 등록·정보 변경·비밀번호 초기화 | 관리자 홈 → 선수 관리 |
| 일반 경기 수정·삭제 | 관리자 홈 → 일반 경기 관리 → 경기 옆 연필·휴지통 |
| 개인 리그·단체전 생성 | 리그전 → 생성 |
| 대회 경기 수정·삭제 | 리그전 → 해당 대회 → 대진의 경기 옆 연필·휴지통 |
| 대회명·팀명 수정 | 해당 대회 상단 수정. 팀명은 시작 후에도 수정 가능 |
| 정산 상품 변경 | 관리자 홈 → 정산 설정 |
| 관리자 본인 비밀번호 변경 | 홈 최하단 → 비밀번호 변경 |
| 미니게임 또는 학기 데이터 초기화 | 관리자 홈 → 데이터 초기화 → 정확한 범위 선택 |

대회 상단 삭제는 대회 전체와 연결된 경기를 지웁니다. 경기 하나를 정정할 때는 대진 옆 버튼을 사용합니다. 선수와 팀 편성은 첫 결과 제출 후 잠기지만 완료·종료된 대회의 결과도 관리자가 정정할 수 있습니다. 기록을 삭제해 미완료가 되면 진행 상태로 돌아갑니다. 개인 리그·단체전 경기는 일반 경기의 동일 상대 하루 1회 제한에 포함되지 않습니다.

## 연결 오류가 발생하면

- 첫 접속만 느리면 약 1분 기다린 뒤 다시 불러옵니다. Render 무료 Web Service는 15분간 요청이 없으면 쉬었다가 다음 요청에 다시 시작하며 약 1분이 걸릴 수 있습니다. 대회 시작 전 관리자가 먼저 접속해 지연을 확인해 두면 좋습니다. [Render 무료 서비스 안내](https://render.com/docs/free)
- 경기 저장 중 연결 오류가 나면 해당 대진이나 최근 기록에서 저장 여부를 먼저 확인합니다. 최신 정보 불러오기 버튼이 있으면 먼저 누릅니다. 일반 경기와 같은 대진의 중복 제출은 서버에서 차단합니다.
- 탁구공 게임 점수 저장 실패 시 **점수 다시 저장**을 누릅니다. 같은 앱 실행 중에는 화면을 나갔다 돌아와도 재시도할 수 있습니다. 앱 완전 종료·로그아웃·계정 변경 전에는 저장을 마칩니다. 저장되지 않은 보물상자는 **상자 보상 다시 저장**으로 처리합니다.
- 새 버전 안내를 닫았으면 홈 하단의 **새 버전 업데이트 안내**를 누르거나 앱에서 나갔다 돌아옵니다. 입력 화면을 자동으로 새로고침하지 않습니다.
- 여러 사용자가 동시에 접속되지 않으면 Render 서비스 상태·배포 로그·DB 상태·결제 알림을 확인합니다. 접속 오류를 해결하기 위해 데이터 초기화를 누르지 않습니다.

## 계속 유지할 항목

- Render·GitHub 계정, 관리자 비밀번호와 복구 수단을 다음 운영자에게 인계합니다. 선수 비밀번호는 관리자 화면에서 초기화할 수 있지만 유일한 관리자 계정의 비밀번호를 잃으면 별도 복구 작업이 필요합니다.
- Render 결제 수단과 DB 저장공간·서비스 알림을 확인합니다. 저장소 설정은 유료 PostgreSQL이지만 실제 DB와 요금제는 Render에서 대조해야 합니다. 무료 PostgreSQL은 장기 보관용으로 사용하지 않습니다. [무료 DB 제한](https://render.com/docs/free#free-postgres)
- 유료 PostgreSQL의 **Recovery** 화면에서 복구 가능한 시점이 있는지 확인합니다. 대회 후와 학기 초기화 전에는 논리 백업을 내려받아 접근이 제한된 별도 저장소에도 보관합니다. 백업에는 계정·세션 정보가 있으므로 Git이나 공개 채팅에 올리지 않습니다. [Render 백업·복구 안내](https://render.com/docs/postgresql-backups)
- 사이트 실행에 Codex는 필요하지 않습니다. 호스팅·DB·도메인은 별도로 유지해야 합니다. OS와 외부 서비스의 향후 정책 변경까지 코드로 보장할 수는 없으므로 서비스 알림은 받을 수 있게 둡니다.

## 초기화와 복원

1. 사용자 입력을 잠시 멈추고 초기화 대상·범위·건수를 확인합니다. 전체 초기화는 선수·경기·대회·선수 세션·미니게임을 지우고 관리자와 상품 설정을 유지합니다.
2. Render에서 대상 DB의 백업 export를 생성하고 완료·다운로드를 확인합니다. DB 이름과 백업 시각을 기록하되 비밀번호나 연결 문자열은 기록하지 않습니다.
3. 복원이 필요하면 운영과 다른 새 DB에 복구합니다. Render PITR도 새 DB를 만드는 방식입니다. 선수·경기·대진·랭킹·정산을 확인한 뒤 서비스를 복원 DB에 연결합니다. 확인 전에는 기존 DB를 삭제하지 않습니다.
4. 초기화 중 ‘다른 요청이 처리 중’ 안내가 나오면 기록은 삭제되지 않았습니다. 다른 사용자 작업이 끝난 뒤 재시도합니다. 예상과 다른 오류라면 반복 초기화하지 말고 로그와 DB 상태를 먼저 확인합니다.
